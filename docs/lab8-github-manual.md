# Ручные шаги GitHub для лабораторной 8

## Pull Request и code-review

1. Добавьте напарника в `Settings → Collaborators → Add people` и дождитесь принятия приглашения.
2. Запушьте `feature/api-tests`, затем откройте PR `feature/api-tests → main` с названием `test: API tests, test database and CI`.
3. Назначьте напарника в поле **Reviewers**. Проверьте вкладку **Checks**: job `test` должен быть зелёным.
4. Откройте PR напарника, оставьте два комментария к конкретным строкам, один через **Insert a suggestion**, затем отправьте review как **Approve** или **Request changes**. Это взаимодействие должен выполнить реальный участник пары.
5. В **Settings → Branches** создайте активное правило для `main`: PR обязателен, одно одобрение, успешный check `test`, запрет force push, без bypass. Для слияния выберите **Squash and merge**.
6. При временном эксперименте с красным CI измените ожидаемый статус одного теста на неверный, запустите локально и убедитесь, что тест падает. Для GitHub эксперимента используйте отдельную временную ветку или PR, проверьте красный check и неактивную кнопку merge, исправьте тест и проверьте зелёный CI. Не оставляйте сломанный тест в итоговой ветке.

## Безопасный эксперимент конфликта

Проводите его в учебном репозитории напарника или отдельном временном репозитории. Создайте две feature-ветки от `main`, измените одну и ту же строку README по-разному, слейте первый PR, затем попробуйте открыть второй. Разрешите конфликт в feature-ветке, проверьте diff и откройте обновлённый PR. Не меняйте `main` напрямую и не создавайте конфликт в рабочем AgroMarket.

## Ответы по реальным результатам

После локального запуска тестов внесите в README фактические число тестов и coverage. После code-review заполните ответы о полученных и оставленных замечаниях; до взаимодействия с напарником их нельзя считать выполненными.
